# IncentiveDocument Model

A program document attached to an incentive (e.g. terms & conditions, eligible product lists, program rules).

## Entity Fields

| Field | Type | Required | Constraints | Notes |
|-------|------|----------|-------------|-------|
| id | UUID | yes | primary key | Generated by database |
| incentiveId | UUID | yes | foreign key | References Incentive |
| name | string | yes | max 255 | Original filename (sanitized) |
| documentType | string | yes | max 50 | Category: terms-conditions, eligible-products, program-rules, faq |
| fileType | string | yes | max 10 | File extension: pdf, xlsx, xls, docx, doc |
| size | string | yes | max 20 | Human-readable size (e.g. "1.2 MB", "245 KB") |
| storagePath | string | no | max 500 | MinIO object key (e.g. "{incentiveId}/{docId}/{filename}"); null for metadata-only docs |
| createdAt | datetime | yes | — | Set on creation |
| updatedAt | datetime | yes | — | Updated on modification |

## Relationships

- Belongs to one Incentive (cascade delete from parent)

## Upload Constraints

| Constraint | Value |
|------------|-------|
| Allowed extensions | pdf, xlsx, xls, docx, doc |
| Allowed MIME types | application/pdf, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, application/vnd.ms-excel, application/vnd.openxmlformats-officedocument.wordprocessingml.document, application/msword |
| Max file size | 10 MB per file |
| Max total upload size | 50 MB per request |
| Max files per upload | 10 |
| Allowed categories | terms-conditions, eligible-products, program-rules, faq |

## File Storage

- File binaries are stored in MinIO (S3-compatible) under the `incentive-documents` bucket
- Object key format: `{incentiveId}/{documentId}/{sanitizedFilename}`
- Documents created via the JSON payload (create/update incentive) store metadata only — no file binary
- Documents uploaded via the multipart endpoint store both metadata and the file binary in MinIO
- The `storagePath` field is null when no file binary is stored; non-null indicates a downloadable file

## API Response Shape

### DocumentSummaryResponse

Returned inside both `IncentiveResponse` and `IncentiveDetailResponse`.

| Field | Type | Notes |
|-------|------|-------|
| id | UUID | |
| name | string | Sanitized filename |
| documentType | string | Category key (e.g. "terms-conditions") |
| fileType | string | Extension (e.g. "pdf") |
| size | string | Human-readable (e.g. "1.2 MB") |
| downloadUrl | string | Relative URL for downloading; null when no file binary is stored |

### DocumentInput (used in create/update requests)

Documents can be included as metadata in the incentive JSON payload.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| name | string | yes | Original filename (sanitized server-side) |
| documentType | string | yes | Category key (terms-conditions, eligible-products, program-rules, faq) |
| fileType | string | yes | Extension (pdf, xlsx, xls, docx, doc) |
| size | string | yes | Human-readable (e.g. "1.2 MB") |

## API Endpoints

- Documents metadata is created/replaced via `POST /api/v1/incentives` and `PUT /api/v1/incentives/{id}` (as part of the `documents` field in the request body)
- `POST /api/v1/incentives/{id}/documents` (multipart) — Upload file binaries to MinIO; accepts `files` (MultipartFile[]) and `categories` (String[])
- `GET /api/v1/incentives/{id}/documents/{documentId}/download` — Stream download a document file (returns file binary with Content-Disposition header)
- `DELETE /api/v1/incentives/{id}/documents/{documentId}` — Delete a single document (removes both DB record and MinIO object)

See `endpoints/incentives.yaml` for full endpoint specifications.
