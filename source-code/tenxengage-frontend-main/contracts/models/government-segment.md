# GovernmentSegment Model

Represents restriction configuration for deals involving government entities, for anti-bribery compliance.

## GovernmentSegmentResponse

| Field | Type | Required | Constraints | Notes |
|-------|------|----------|-------------|-------|
| id | UUID | yes | primary key | Generated by database |
| segmentName | string | yes | max 255 | Name of the government segment (e.g. "Federal", "State/Local", "Education") |
| restrictionMode | GovernmentDealRestrictionMode | yes | enum | See enums.md |
| maxRewardPerRecipient | BigDecimal | no | string representation, nullable | Per-recipient reward cap for this segment (null = use default value cap) |
| requiresApproval | boolean | yes | — | Whether deals in this segment require explicit admin approval |
| updatedAt | datetime | yes | ISO 8601 | When the configuration was last modified |

## Relationships

- Belongs to one Client (tenant-scoped)

## Business Rules

- NONE: No restrictions — government deals treated like any other
- STRICT: All rewards to government segment are blocked
- APPROVAL_REQUIRED: Rewards require CLIENT_ADMIN approval before payout
- AUDIT_ONLY: Rewards are allowed but flagged for audit review
- When a deal is tagged with a government segment, the restriction mode determines the workflow
