# PurchaseOrder Model

Represents a purchase order ingested from CRM data. Purchase orders are the basis for the claims and rewards system.

## Entity: PurchaseOrder

| Field            | Type     | Required | Constraints                 | Notes                                   |
| ---------------- | -------- | -------- | --------------------------- | --------------------------------------- |
| id               | UUID     | yes      | primary key                 | Generated by database                   |
| clientId         | UUID     | yes      | foreign key                 | References Client (tenant)              |
| partnerCompanyId | UUID     | yes      | foreign key                 | References PartnerCompany               |
| orderNumber      | string   | yes      | max 30                      | External order number                   |
| orderDate        | date     | yes      | —                           | Date of the order                       |
| status           | string   | yes      | max 20, default "COMPLETED" | Order status                            |
| totalAmount      | decimal  | yes      | default 0                   | Total order value                       |
| needsRetagging   | boolean  | yes      | default true                | Whether eligibility needs recalculation |
| metadata         | jsonb    | no       | default {}                  | Flexible key-value data from CRM        |
| createdAt        | datetime | yes      | —                           | ISO 8601                                |
| updatedAt        | datetime | yes      | —                           | ISO 8601                                |

## Entity: PurchaseOrderLine

| Field           | Type     | Required | Constraints    | Notes                          |
| --------------- | -------- | -------- | -------------- | ------------------------------ |
| id              | UUID     | yes      | primary key    | Generated by database          |
| purchaseOrderId | UUID     | yes      | foreign key    | References PurchaseOrder       |
| productId       | UUID     | yes      | foreign key    | References Product             |
| quantity        | integer  | yes      | —              | Line item quantity             |
| unitPrice       | decimal  | yes      | precision 12,2 | Price per unit                 |
| lineTotal       | decimal  | yes      | precision 14,2 | quantity \* unitPrice          |
| transactionId   | string   | no       | max 30         | External transaction reference |
| createdAt       | datetime | yes      | —              | ISO 8601                       |
| updatedAt       | datetime | yes      | —              | ISO 8601                       |

## Relationships

- PurchaseOrder belongs to Client (tenant) and PartnerCompany
- PurchaseOrder has many PurchaseOrderLine (one-to-many, cascade ALL)
- PurchaseOrderLine belongs to Product

## Multi-Tenancy

- Tenant-scoped via `client_id`

## Notes

- POs are ingested via data upload (CSV/XLSX) or connector sync, not created via API
- The `needsRetagging` flag is set when PO data changes and cleared after eligibility tagging runs
- The `metadata` field stores arbitrary CRM fields as key-value pairs
