# RewardWallet Model

Per-currency reward wallet for an individual user or partner company. Replaces `RewardBalance` (evolved in-place via V6 migration).

| Field              | Type     | Required | Constraints                   | Notes                                                               |
|--------------------|----------|----------|-------------------------------|---------------------------------------------------------------------|
| id                 | UUID     | yes      | primary key                   | Generated by database                                               |
| walletType         | string   | yes      | enum: INDIVIDUAL, COMPANY     | Discriminates individual seller wallets from pooled company wallets |
| currencyId         | string   | yes      | max 50                        | Currency code — "cash", "points", "credits", "tickets"              |
| availableBalance   | string   | yes      | decimal string; default "0"   | Spendable amount; never negative                                    |
| reservedBalance    | string   | yes      | decimal string; default "0"   | Locked against in-flight redemptions                                |
| createdAt          | datetime | yes      | —                             | ISO 8601                                                            |
| updatedAt          | datetime | yes      | —                             | ISO 8601                                                            |

## Fields Never Exposed in API

The following fields exist on the entity but are **never returned in API responses**:

| Field             | Reason                                           |
|-------------------|--------------------------------------------------|
| clientId          | Tenant isolation — resolved server-side          |
| userId            | Internal reference; not needed by callers        |
| partnerCompanyId  | Internal reference; not needed by callers        |
| version           | Optimistic lock counter; internal                |

## Multi-Tenancy

- Tenant-scoped via `client_id` (Hibernate `@Filter` — never exposed in responses)

## Wallet Types

- `INDIVIDUAL` — per-user wallet; one per `(clientId, userId, currencyId)` combination
- `COMPANY` — pooled wallet at the partner-company level; one per `(clientId, partnerCompanyId, currencyId)` combination

## Notes

- Wallet is auto-created on first credit if it does not exist
- `availableBalance` is the spendable amount; `reservedBalance` is locked during in-flight redemptions
- Every balance movement writes an immutable `LedgerEntry` record atomically (see `ledger-entry.md`)
- Balances are strings to avoid floating-point precision issues (DECIMAL(18,2) in the database)
- `RewardBalance` model is deprecated — this model is its replacement
