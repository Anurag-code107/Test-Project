# BreachIncident Model

Represents a data breach incident record for GDPR Article 33/34 compliance.

## Entity Fields

| Field                 | Type           | Required | Constraints | Notes                                   |
| --------------------- | -------------- | -------- | ----------- | --------------------------------------- |
| id                    | UUID           | yes      | primary key | Generated by database                   |
| description           | string         | yes      | TEXT        | Detailed description of the breach      |
| severity              | BreachSeverity | yes      | enum        | See enums.md                            |
| dataAffected          | string         | no       | TEXT        | Description of affected data categories |
| detectedAt            | datetime       | yes      | ISO 8601    | When the breach was detected            |
| reportedToAuthorityAt | datetime       | no       | ISO 8601    | When reported to supervisory authority  |
| individualsNotifiedAt | datetime       | no       | ISO 8601    | When affected individuals were notified |
| status                | BreachStatus   | yes      | enum        | See enums.md                            |
| resolutionNotes       | string         | no       | TEXT        | Resolution details                      |
| createdBy             | UUID           | yes      | —           | User who created the record             |
| createdAt             | datetime       | yes      | ISO 8601    | Set on creation                         |
| updatedAt             | datetime       | yes      | ISO 8601    | Updated on modification                 |

## Business Rules

- GDPR requires notification to supervisory authority within 72 hours of detection
- HIGH and CRITICAL severity breaches should also notify affected data subjects
- All breach records are immutable once created (status transitions only, no field edits)
