# Client Model

Represents a tenant in the multi-tenant system. Each client is an independent organization that runs partner incentive programs.

| Field                     | Type             | Required | Constraints    | Notes                                     |
| ------------------------- | ---------------- | -------- | -------------- | ----------------------------------------- |
| id                        | UUID             | yes      | primary key    | Generated by database                     |
| name                      | string           | yes      | max 255        | Display name of the client                |
| subdomain                 | string           | yes      | unique, max 63 | Used for tenant resolution (e.g., `acme`) |
| logoUrl                   | string           | no       | URL, max 500   | Client logo for branding                  |
| status                    | ClientStatus     | yes      | enum           | See enums.md                              |
| subscriptionTier          | SubscriptionTier | yes      | enum           | Determines enabled features               |
| notificationRetentionDays | integer          | no       | default 90     | How long to keep notifications            |
| dpaSignedAt               | datetime         | no       | —              | When DPA was signed                       |
| dpaVersion                | string           | no       | —              | DPA version string                        |
| dpaSignedBy               | string           | no       | —              | Who signed the DPA                        |
| dataRegion                | string           | no       | max 10         | Data residency region code                |
| createdAt                 | datetime         | yes      | —              | ISO 8601, set on creation                 |
| updatedAt                 | datetime         | yes      | —              | ISO 8601, updated on modification         |

## Relationships

- Has many Users (one-to-many via `users.client_id`)
- Has many PartnerCompanies (one-to-many via `partner_companies.client_id`)
- Has many ClientFeatureOverrides (one-to-many)
- Has many ClientRoles (one-to-many via `client_roles.client_id`)
- Has many ClientPermissionGrants (one-to-many)

## Notes

- The Client entity is NOT tenant-scoped — it IS the tenant.
- Only TENX_ADMIN users can create, update, or delete clients.
- The `subdomain` field is used to resolve the current tenant from the `X-Client-Subdomain` header or JWT claims.
