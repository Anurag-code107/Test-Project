# ClientRole Model

Represents a per-tenant role with associated permissions. Replaces the former global Role entity with a flexible, tenant-scoped permission system.

## Entity: ClientRole

| Field        | Type     | Required | Constraints   | Notes                                                |
| ------------ | -------- | -------- | ------------- | ---------------------------------------------------- |
| id           | UUID     | yes      | primary key   | Generated by database                                |
| clientId     | UUID     | yes      | foreign key   | References Client (tenant)                           |
| name         | string   | yes      | max 100       | Display name (e.g. "Sales Manager")                  |
| description  | string   | no       | TEXT          | Role description                                     |
| baseRoleName | string   | no       | max 50        | Original system role reference (e.g. "CLIENT_ADMIN") |
| isSystem     | boolean  | yes      | default false | System roles cannot be deleted                       |
| isDefault    | boolean  | yes      | default false | Default role assigned to new users of this type      |
| roleType     | string   | yes      | max 20        | INTERNAL (client-side) or EXTERNAL (partner-side)    |
| createdAt    | datetime | yes      | —             | ISO 8601                                             |
| updatedAt    | datetime | yes      | —             | ISO 8601                                             |

## Entity: ClientRolePermission

| Field         | Type     | Required | Constraints  | Notes                                                |
| ------------- | -------- | -------- | ------------ | ---------------------------------------------------- |
| id            | UUID     | yes      | primary key  | Generated by database                                |
| clientRoleId  | UUID     | yes      | foreign key  | References ClientRole                                |
| permissionKey | string   | yes      | max 100      | Permission identifier (e.g. "action.incentive.view") |
| granted       | boolean  | yes      | default true | Whether this permission is granted to the role       |
| createdAt     | datetime | yes      | —            | ISO 8601                                             |
| updatedAt     | datetime | yes      | —            | ISO 8601                                             |

## Relationships

- ClientRole belongs to one Client
- ClientRole has many ClientRolePermission (one-to-many, cascade ALL)
- ClientRole has many Users (one-to-many via `users.client_role_id`)

## Default System Roles

Four system roles are seeded per client (isSystem = true):

| baseRoleName      | roleType | Description                                 |
| ----------------- | -------- | ------------------------------------------- |
| CLIENT_ADMIN      | INTERNAL | Full admin access for the tenant            |
| ACTIVITY_APPROVER | INTERNAL | Can review and approve activity submissions |
| PARTNER_ADMIN     | EXTERNAL | Admin for a partner company                 |
| PARTNER_SELLER    | EXTERNAL | Sales rep within a partner company          |

## Notes

- Custom roles can be created by cloning existing roles
- System roles (isSystem = true) cannot be deleted but their permissions can be modified
- The `roleType` determines which permissions are available (INTERNAL vs EXTERNAL scope)
