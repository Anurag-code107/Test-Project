# FeatureFlag Model

Defines a feature that can be enabled or disabled based on subscription tier or per-client overrides.

| Field               | Type     | Required | Constraints               | Notes                                             |
| ------------------- | -------- | -------- | ------------------------- | ------------------------------------------------- |
| id                  | UUID     | yes      | primary key               | Generated by database                             |
| featureKey          | string   | yes      | unique, max 100           | Machine-readable key (e.g., `advanced_analytics`) |
| description         | string   | no       | max 500                   | Human-readable description                        |
| starterEnabled      | boolean  | yes      | default false             | Enabled for STARTER tier                          |
| professionalEnabled | boolean  | yes      | default false             | Enabled for PROFESSIONAL tier                     |
| enterpriseEnabled   | boolean  | yes      | default true              | Enabled for ENTERPRISE tier                       |
| category            | string   | no       | max 50, default "general" | Feature category for grouping                     |
| createdAt           | datetime | yes      | —                         | ISO 8601, set on creation                         |
| updatedAt           | datetime | yes      | —                         | ISO 8601, updated on modification                 |

## ClientFeatureOverride

Per-client override for a feature flag. Allows enabling or disabling a feature regardless of subscription tier.

| Field         | Type     | Required | Constraints | Notes                  |
| ------------- | -------- | -------- | ----------- | ---------------------- |
| id            | UUID     | yes      | primary key | Generated by database  |
| clientId      | UUID     | yes      | foreign key | References Client      |
| featureFlagId | UUID     | yes      | foreign key | References FeatureFlag |
| enabled       | boolean  | yes      | —           | Override value         |
| createdAt     | datetime | yes      | —           | ISO 8601               |
| updatedAt     | datetime | yes      | —           | ISO 8601               |

### Constraints

- Unique constraint: `(client_id, feature_flag_id)` — one override per feature per client

## Feature Resolution Logic

1. Check if a `ClientFeatureOverride` exists for the client + feature -> use override value
2. Otherwise, check the feature flag's tier-specific column based on the client's `subscriptionTier`

## Notes

- FeatureFlag is NOT tenant-scoped — it is a global definition.
- ClientFeatureOverride IS tenant-scoped.
- Only TENX_ADMIN users can manage feature flag definitions and overrides.
- The login response includes `enabledFeatures: string[]` — a list of enabled feature keys for the authenticated user's client.
