# RetentionPolicy Model

Represents a data retention policy for a specific category of data within a client tenant.

## RetentionPolicyResponse

| Field | Type | Required | Constraints | Notes |
|-------|------|----------|-------------|-------|
| id | UUID | yes | primary key | Generated by database |
| category | DataCategory | yes | enum | See enums.md |
| retentionDays | integer | yes | min 1 | Number of days data is retained before action is taken |
| actionType | RetentionActionType | yes | enum | See enums.md — ANONYMIZE or DELETE |
| lastExecutedAt | datetime | no | ISO 8601 | When the retention job last ran for this category |
| updatedAt | datetime | yes | ISO 8601 | When the policy was last modified |

## UpdateRetentionPolicyRequest

| Field | Type | Required | Constraints | Notes |
|-------|------|----------|-------------|-------|
| retentionDays | integer | yes | min 1, must be within platform bounds | Number of days to retain |
| actionType | RetentionActionType | yes | enum | ANONYMIZE or DELETE |

## Relationships

- Belongs to one Client (tenant-scoped)
- Platform defaults are stored with a null clientId (managed by TENX_ADMIN)

## Business Rules

- Client-configured retention values must fall within platform-defined min/max bounds
- The retention job runs nightly and processes records older than retentionDays
- ANONYMIZE replaces PII with hashed values; DELETE removes the records entirely
