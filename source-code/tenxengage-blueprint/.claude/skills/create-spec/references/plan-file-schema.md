# Plan file schema

Reference loaded by step 15 (`write-plan-file`). The plan file is the durable artifact between spec generation and file write. It contains both a dense outline (a reviewer can read end-to-end in minutes) and full verbatim spec.md + technical.md content (so step 16 has nothing to regenerate).

---

## Frontmatter

```yaml
---
slug: {feature-slug}
stepsCompleted: [parse-input, load-brd-context, load-project-context, resolve-open-questions, detect-feature-shape, load-shape-references, scope-decomposition, security-analysis, events-analysis, test-strategy, permissions-analysis, derive-slug, generate-spec-content, generate-technical-content, write-plan-file]
filesWritten: []
---
```

`filesWritten` is updated by step 16 to `["spec.md", "technical.md"]` after writing.

## What goes in this plan file vs what /create-stories generates later

| Artifact | Plan mode (this file) | Generated by /create-stories |
|---|---|---|
| spec.md | full verbatim | — |
| technical.md | full verbatim | — |
| stories.md | not here | from spec FRs + data model |
| tracker.md | not here | all rows `not-started` |
| tasks/foundation.md | not here | from spec enums + technical migrations + entities |
| stories/US-NN-*.md | not here | from spec endpoints + FRs + edge cases |
| test-plan.md | not here | from spec integration test scenarios |

The plan is spec + technical only. Story decomposition is a separate step after review.

---

## Rules for writing the plan file

- spec.md and technical.md content is VERBATIM from steps 13 and 14. Do NOT re-summarize or reinterpret.
- The plan file is the only place these contents live until step 16 writes them to `features/{slug}/`.
- Frontmatter `stepsCompleted` array MUST include all 15 step names — used by SKILL.md for resumption.
- The plan file path is provided by the plan-mode harness system message. Use it exactly.
