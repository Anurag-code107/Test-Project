# LedgerEntry Model

Immutable record of every balance movement on a `RewardWallet`. The financial audit trail — never updated or deleted after write.

| Field                  | Type     | Required | Constraints              | Notes                                                                          |
|------------------------|----------|----------|--------------------------|--------------------------------------------------------------------------------|
| id                     | UUID     | yes      | primary key              | Generated by database                                                          |
| rewardWalletId         | UUID     | yes      | foreign key              | References RewardWallet                                                        |
| entryType              | string   | yes      | enum: CREDIT, RESERVE, DEBIT, RELEASE, RETURN_CREDIT | The five balance movement types      |
| amount                 | string   | yes      | decimal string; > 0      | Always positive; direction implied by `entryType`                              |
| currencyId             | string   | yes      | max 50                   | Denormalized from wallet for currency-filtered queries                         |
| referenceType          | string   | no       | max 50                   | Source domain: INCENTIVE, TRAINING, ACTIVITY, JOURNEY, DEAL, REDEMPTION, RETURN |
| referenceId            | UUID     | no       | —                        | FK to the source record                                                        |
| note                   | string   | no       | max 500                  | Human-readable context                                                         |
| availableBalanceBefore | string   | yes      | decimal string           | Wallet `availableBalance` snapshot before this entry                           |
| availableBalanceAfter  | string   | yes      | decimal string           | Wallet `availableBalance` snapshot after this entry                            |
| reservedBalanceBefore  | string   | yes      | decimal string           | Wallet `reservedBalance` snapshot before this entry                            |
| reservedBalanceAfter   | string   | yes      | decimal string           | Wallet `reservedBalance` snapshot after this entry                             |
| createdAt              | datetime | yes      | —                        | ISO 8601; serves as the entry timestamp                                        |
| updatedAt              | datetime | yes      | —                        | ISO 8601; semantically unused (record never updated)                           |

## Fields Never Exposed in API

| Field    | Reason                                  |
|----------|-----------------------------------------|
| clientId | Tenant isolation — resolved server-side |

## Entry Type Semantics

| entryType     | availableBalance | reservedBalance | Description                                   |
|---------------|-----------------|-----------------|-----------------------------------------------|
| CREDIT        | +amount         | unchanged       | Earning event; wallet auto-created if absent  |
| RESERVE       | -amount         | +amount         | Redemption submitted; funds locked in-flight  |
| DEBIT         | unchanged       | -amount         | Vendor confirmed; funds consumed              |
| RELEASE       | +amount         | -amount         | Redemption failed/cancelled; funds restored   |
| RETURN_CREDIT | +amount         | unchanged       | Vendor confirmed return (F-06)                |

## Idempotency

Credits are idempotent on `(rewardWalletId, referenceType, referenceId)` — a duplicate earning event delivery writes no second entry and returns the current wallet state unchanged.

## Multi-Tenancy

- Tenant-scoped via `client_id` (Hibernate `@Filter` — never exposed in responses)

## Notes

- Records are **immutable** — no UPDATE or DELETE permitted after write
- Retained for a minimum of 7 years (financial audit trail; GDPR Article 17(3)(b) exemption)
- Balance snapshot fields (`*Before`/`*After`) enable point-in-time reconciliation without replaying the full ledger
- Fully used by F-05 (Transaction History); stubbed in F-01
