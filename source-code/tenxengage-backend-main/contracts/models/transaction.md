# RewardTransaction Model

Represents a reward transaction created when a user claims a deal. Each transaction records the reward earned from a specific incentive for a specific currency.

| Field           | Type     | Required | Constraints   | Notes                                                      |
| --------------- | -------- | -------- | ------------- | ---------------------------------------------------------- |
| id              | UUID     | yes      | primary key   | Generated by database                                      |
| clientId        | UUID     | yes      | foreign key   | References Client (tenant)                                 |
| claimActionId   | UUID     | no       | foreign key   | References ClaimAction (null for non-claim rewards)        |
| userId          | UUID     | yes      | foreign key   | References User who earned the reward                      |
| incentiveId     | UUID     | yes      | foreign key   | References Incentive                                       |
| currencyId      | string   | yes      | max 50        | Currency identifier (e.g. "cash", "points")                |
| amountPotential | decimal  | yes      | —             | Reward before budget capping                               |
| amountAwarded   | decimal  | yes      | —             | Actual reward after budget capping                         |
| budgetCapped    | boolean  | yes      | default false | Whether reward was reduced by budget limits                |
| completionId    | UUID     | no       | —             | References UserIncentiveCompletion (for non-sales rewards) |
| createdAt       | datetime | yes      | —             | Set on creation                                            |
| updatedAt       | datetime | yes      | —             | Updated on modification                                    |

## Relationships

- Belongs to ClaimAction (optional, many-to-one)
- Belongs to User (many-to-one)
- Belongs to Incentive (many-to-one)

## Multi-Tenancy

- Tenant-scoped via `client_id`

## Notes

- Transactions are created atomically during claim processing
- When a deal is unclaimed, corresponding transactions are reversed
- Budget utilization is updated in real-time as transactions are created
- Monetary totals (cash + points) are aggregated for claim summaries
