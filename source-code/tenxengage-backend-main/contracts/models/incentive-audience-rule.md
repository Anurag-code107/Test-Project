# IncentiveAudienceRule Model

Defines audience targeting rules for an incentive — one row per discrete eligibility criterion. The `ParticipantEligibilityChecker` reads these rows at claim time to decide which partners qualify (BUG-061 ancestor walk + BUG-062 OR-across-levels).

| Field | Type | Required | Constraints | Notes |
|-------|------|----------|-------------|-------|
| id | UUID | yes | primary key | Generated by database |
| incentiveId | UUID | yes | foreign key | References Incentive |
| ruleType | AudienceRuleType | yes | enum | LOCATION, PARTNER_TYPE, ROLE (REGION/COUNTRY retired in BUG-034) |
| ruleValue | string | yes | max 255 | UUID for LOCATION (LocationValue.id, any depth) and ROLE (ClientRole.id); free-text label for PARTNER_TYPE (BUG-079) |
| locationLevelId | UUID | conditional | foreign key | Required when ruleType=LOCATION; null otherwise. References LocationLevel — disambiguates the depth in the tenant's hierarchy |
| createdAt | datetime | yes | — | Set on creation |

## Relationships

- Belongs to one Incentive
- LOCATION rules reference one LocationValue (via `ruleValue` UUID) and one LocationLevel (via `locationLevelId`)
- ROLE rules reference one ClientRole (via `ruleValue` UUID)

## Wire format vs storage

The persisted `rule_value` column has always been a UUID-capable string. BUG-034 started populating it with a UUID for LOCATION rules (post-resolution). BUG-079 makes the wire format match: `AudienceRuleRequest.ruleValue` carries the UUID directly instead of a name that the backend resolves. Names live in frontend state (for picker rendering) and Excel files (for human-readable input) — they're resolved to UUIDs at the boundary (`builderRequestMapper` for picker selections, `excelTemplateParser` for uploads) and never travel the wire.
